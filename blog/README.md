# 看完发布会，我用一个变量在浏览器里折了台手机

先说结论：这是个网页。

没有 WebGL，没有 three.js，没有 3D 模型，没有视频。就是 React + CSS 3D + GSAP，
真正干活的引擎是 `src/fold/mapping.ts` —— 一个三百来行的文件。

![半开状态](assets/01-fold-mid.png)

## 一切从发布会那几秒开始

发布会看完，我脑子里剩下的不是参数，是那个画面：一台手机合着，展开，屏幕从一块变成两块，
然后内容自己重新长了一遍 —— 左半边那组 widget 原封不动，右半边长出新的东西来。

那一下给我的感觉是：折叠不像个五金件的动作，它像个软件动作。

然后我就开始琢磨一个特别不务正业的问题：这东西，用网页能做吗？

不是"放个视频"那种能做。是鼠标往下滚，手机真的从合到开，整个过程里屏幕空间、内容布局、
铰链、景深、光影得**同时连续变化**，中间不能有一帧是跳的。

## 先看效果

滚动就是唯一的输入。你往下滚，它展开；往上滚，它合上。

![合上 → 展开](assets/00-fold.gif)

合上的时候你看到的是外屏。展开的过程中，内容不是被放大，是被**重新布局** ——
同一张封面从左半横跨折痕飞到右边，列表在它腾出来的位置上长出来。最后两块屏、同一块画布。

（[MP4 版本](assets/00-fold.mp4)，画质好一点）

## 一个我当时没想明白的问题：那外屏上的东西去哪了

合上的时候，外屏朝向你。它其实长在"会转动的那一半"的**背面**。

所以展开的时候，它是物理上转走的 —— 内容跟着一起转到你背后去了。

第一版我就卡在这儿：封面转着转着就没了。不是淡出，是物理意义上的离开画面。

后来想通了：**内容不一定要跟着玻璃走**。把封面从面板里"提"出来，停在相机空间里 ——
面板从它底下抽走，它悬在原地，然后横跨折痕飞过去，落到右侧的详情面板上。

![内容横跨折痕](assets/00-cover-flight.gif)

注意它不是"飞出一个机身"—— 全程被两块和面板完全一样的玻璃夹着，飞不出屏幕轮廓
（[MP4](assets/00-cover-flight.mp4)）。

## 第二个问题：内屏不是"淡入"的

真实世界里，镜头的焦点一次只能在一个地方。

外屏还清楚的时候，底下刚露出来的内屏就该是**虚的**。等它转过来，焦点再交过去。
所以我没做交叉淡入 —— 做的是**失焦**：外屏一路糊下去，两个内屏各自从铰链往外慢慢对上焦。

![内外屏对焦交接](assets/00-focus-pull.gif)

这段节奏我调了整整一晚上。一开始外屏糊得太快，手机上还没看出动静呢，外屏已经是块马赛克了；
内屏又反过来，一露头就是一团满级重影，像是"啪"地贴上来的。

最后改成了两条独立的曲线：外屏的模糊**后置** —— 等铰链真的开始摆了才慢慢糊；
内屏的模糊**从浅到深**再收干净，而不是一上来就拉满。现在看着才像是"对焦"，不是"切换"
（[MP4](assets/00-focus-pull.mp4)）。

![清晰区从铰链往外长](assets/05-focus-pull.png)

左边那半已经对上了，右边那半还在糊 —— 因为玻璃是绕着铰链转的，边缘走得最远，也就最晚上焦。

## 所以它到底是怎么跑起来的

四句话：

**1. 没有 3D 模型，只有两块刚性平板。** 手机就是两个 `div`，右半绕铰链转一个
`rotateY(-fold)`，`fold` 从 180° 走到 0°，完事。

**2. 所有东西都由一个标量驱动。** 一个 `progress`，0 到 1。铰链角度、相机推拉、
外屏旋转、内容布局、运动模糊、折痕深浅，全是它的函数。没有任何组件自己存动画状态 ——
所以永远不可能出现"这块动到一半、那块没跟上"。

**3. 每帧只写 CSS 变量，不触发 React 重渲染。** 滚动 60 帧，就是 60 次
`style.setProperty`，React 一次都没醒。

**4. 内容是同一张画布，被两块玻璃各裁一半。** 画布做成两倍宽，两个面板各裁自己那一半，
所以跨折痕的元素天然是连续的，不需要"对齐"。

## 踩得最惨的一个坑，我一定要讲

"飞行层"（那块横跨折痕的封面）**必须是相机的兄弟节点，不能是它的子元素**。

为什么？折叠到 165° 的时候，转动的那一半是**朝观众翘起来**的，它的远端在 z 轴上已经到
了 +93px。你给封面加"抬起几像素"，它其实还在玻璃**后面**，被外屏结结实实盖住 ——
表现就是：封面一闪就没了。

把它放到相机**外面**（同样的盒子、同样的 transform、同样的透视），它在绘制顺序上就永远
排在机身之后，这个深度排序问题整个消失。

这种坑，光看代码是看不出来的，必须一帧一帧盯着屏幕找。

## 你还能自己玩

- 顶栏切三个页面：折叠研究 / 外屏交接 / 内外屏对焦
- 下面有滑块，可以停在**任意一帧**
- 预设了几个关键角度：180° 外屏、120° 散焦、66° 对焦中、0° 全清晰
- 点"自动往返"让它自己开合
- 手机上可以直接**上下拖拽机身**
- 还能换 App：播放器 / 邮件 / 图库，看三种不同的内容重排

## 想在自己电脑上跑

```bash
pnpm install
pnpm dev
```

没有构建依赖，没有后端。hash 路由，`pnpm build` 出来的 `dist/` 丢到任何静态托管上都能跑。

## 最后

我到现在还是觉得，"折叠屏"这件事最性感的地方不是硬件，是**内容怎么跟着变**。

一块屏变成两块屏，中间那一瞬间该怎么过渡 —— 这是个设计问题，也是个算法问题，
而且用 CSS 就能把它讲清楚。

代码都在这儿：[you-want/apple-duo-animation](https://github.com/you-want/apple-duo-animation)。
觉得有意思的话给个 star，我继续往上面的坑里填东西。
